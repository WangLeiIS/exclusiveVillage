# PrimaryAgentManager 说明文档

## 概述
PrimaryAgentManager 是主理人 Agent 管理器类，负责管理名为"任我行"的全能型 AI 主理人。这个管理器处理主理人 Agent 的初始化、数据库操作和配置管理。主理人 Agent 是一个特殊的系统级 Agent，具有全局视野，负责系统导航、任务协调和问题诊断。

## 核心功能

- **主理人初始化**：自动创建和初始化主理人 Agent 的数据库和配置
- **数据库管理**：确保主理人专用数据库（`__primary__` 团队）存在并正确初始化
- **配置管理**：提供主理人 Agent 的完整配置，包括系统提示词、角色、金币数量等
- **信息查询**：获取主理人 Agent 的详细信息和配置
- **信息更新**：更新主理人 Agent 的角色、目标描述或金币数量
- **团队名称管理**：提供主理人团队名称用于数据库操作

### 集成点
- 通过 DatabaseManager 的 `connect`、`query`、`run` 方法进行数据库操作
- 使用特殊的团队名称 `__primary__` 作为主理人的数据隔离
- 配置对象 PRIMARY_AGENT_CONFIG 包含主理人的所有静态配置

## 代码风险和异味

### 安全问题
- **配置硬编码**：主理人的完整配置（包括系统提示词）硬编码在源代码中，不利于灵活修改
- **字段过滤不完整**：`updatePrimaryAgent` 方法的 `allowedFields` 列表可能遗漏其他应该可更新的字段
- **缺少输入验证**：`updatePrimaryAgent` 方法没有验证传入的 `updates` 参数类型和值的合法性

### 代码异味
- **单一职责原则违反**：既负责数据库管理又负责配置定义，配置应该从外部加载
- **魔法字符串**：`PRIMARY_TEAM_NAME = '__primary__'` 是硬编码的特殊值，没有文档说明其含义
- **缺少测试**：没有找到对应的测试文件，关键逻辑缺乏测试覆盖

### 错误处理
- `initialize` 方法有 try-catch 但只是重新抛出错误，没有额外的错误恢复或日志记录
- 其他方法缺少显式的错误处理，依赖 DatabaseManager 抛出异常

### 资源管理
- 依赖 DatabaseManager 管理数据库连接生命周期
- 没有显式的关闭或清理方法

## 如何测试

### 单元测试
- **初始化测试**：验证首次初始化时创建数据库和 Agent，再次初始化时复用现有数据
- **数据库确保测试**：模拟数据库不存在和存在两种场景
- **创建和获取测试**：验证创建 Agent 后能正确获取，包含字段类型转换（is_vocal, is_user）
- **更新测试**：测试允许的字段更新成功，不允许的字段被忽略
- **配置获取测试**：验证 getConfig 返回完整的配置对象

### 集成测试
- **与 DatabaseManager 集成**：测试真实的数据库操作，包括连接、查询、更新
- **文件系统测试**：验证在文件系统上正确创建主理人目录和数据库文件
- **迁移场景测试**：模拟数据库迁移场景，验证主理人 Agent 正确初始化

### 边界情况
- 数据库文件已存在但为空
- 数据库文件损坏或无法读取
- 并发初始化调用
- 更新操作传入空对象或无效字段

### Mock 建议
- Mock DatabaseManager 以隔离数据库操作，专注测试业务逻辑
- Mock fs 模块以测试文件系统相关逻辑
- 使用内存数据库进行快速集成测试

### 测试组织
建议创建 `src/agent/__tests__/PrimaryAgentManager.test.ts` 文件，使用 Jest 或类似测试框架。

## 注意事项

### 性能考虑
- 主理人 Agent 在系统启动时初始化，应确保初始化过程快速完成
- 数据库查询应该都很快，因为主理人团队只有一个 Agent
- 配置对象直接返回，无需每次重新构建

### 配置要求
- 主理人使用独立的团队名称 `__primary__`，不应与普通团队冲突
- 系统提示词内容较长，修改时需要谨慎考虑影响
- 金币初始值为 1000，这个值在业务逻辑中可能有特殊含义

### 环境依赖
- 依赖 DatabaseManager 正确配置 AGENTS_DIR 环境变量或默认路径
- 需要文件系统写权限来创建数据库文件
- 使用 CommonJS 模块系统，需要确保在 Node.js 环境中运行

### 常见陷阱
- 不要修改 `PRIMARY_TEAM_NAME` 的值，这会导致数据隔离失效
- 更新 Agent 信息时只能更新 `allowedFields` 列表中的字段
- 主理人 Agent 的 class 字段固定为 'primary'，用于查询时使用
- is_vocal 和 is_user 字段在数据库中是整数，查询后需要转换为布尔值

### 维护建议
- 考虑将 PRIMARY_AGENT_CONFIG 移到独立的配置文件，支持运行时修改
- 增加配置验证逻辑，确保必要字段存在且合法
- 考虑添加配置热重载功能，无需重启即可更新主理人配置
- 添加更详细的日志记录，便于调试和监控
